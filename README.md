# Adrobot Light

Приложение создаёт кампании в Keitaro и позволяет менять состав офферов в их потоках. Группу кампании и источник трафика выбирает оператор, домен определяет Keitaro. Посетители из выбранной страны перенаправляются на Google, остальные попадают на выбранный оффер. В редакторе можно посмотреть новые доли до публикации и восстановить ранее известные привязки, удалённые напрямую в Keitaro.

- `backend/` — FastAPI, клиент Admin API Keitaro и миграции Alembic. В PostgreSQL хранятся учётные записи и известные привязки офферов. Кампании, потоки и опубликованные доли хранятся в Keitaro.
- `frontend/` — интерфейс на Vue и TypeScript. Черновик и закреплённые доли хранятся в открытой вкладке. FastAPI раздаёт собранный интерфейс и API с одного адреса.

## Структура сервера

`backend/app/main.py` собирает FastAPI, подключение к PostgreSQL и клиент Keitaro. В `api/` находятся маршруты и работа с сеансом браузера. `use_cases/` описывает создание учётных записей и кампаний, вход, загрузку потоков и публикацию изменений. В `services/` собраны правила расчёта долей и проверки паролей. `repositories/` выполняет запросы и управляет транзакциями PostgreSQL, `models/` описывает таблицы для приложения и Alembic. `adapters/keitaro.py` отправляет запросы в Admin API и проверяет ответы трекера. Команда `app.manage` использует тот же сценарий создания пользователя.

## Настройка

Из корня репозитория скопируйте пример и заполните `.env`.

```sh
cp .env.example .env
```

- `KEITARO_URL` — базовый адрес трекера, например `https://tracker.example.com`. Приложение само добавит `/admin_api/v1/`.
- `KEITARO_API_KEY` — ключ Admin API с доступом к группам кампаний, источникам трафика, кампаниям, потокам и офферам, а также с правом создавать кампании и менять потоки.
- `SESSION_SECRET` — случайный секрет от 32 символов. Его можно получить командой `openssl rand -hex 32`. Для локального HTTP оставьте `SESSION_SECURE=false`, для HTTPS установите `true`.
- `DATABASE_URL` — строка подключения формата `postgresql+psycopg://пользователь:пароль@сервер:5432/база`. Если пароль содержит специальные символы, закодируйте их для URL. Файл `.env` исключён из Git.

## Запуск с Docker Compose

Нужны Docker и Docker Compose v2. В `.env` задайте пароль `POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`. Оставьте `db` в качестве имени сервера базы. Если меняете `POSTGRES_DB` или `POSTGRES_USER`, обновите соответствующие части `DATABASE_URL`.

```sh
docker compose build
docker compose up -d --wait db
docker compose run --rm app alembic upgrade head
docker compose run --rm app python -m app.manage create-user operator
docker compose up -d app
```

При создании пользователя команда дважды запрашивает пароль. Интерфейс доступен по адресу `http://localhost:8000/`, документация API — по адресу `http://localhost:8000/docs`.

`docker compose down` останавливает сервисы и сохраняет данные в именованном томе `postgres_data`. Следующий `docker compose up -d` использует тот же том. При обновлении приложения примените миграции до запуска новой версии. Пользователя достаточно создать один раз.

## Запуск без Docker

Нужны установленный и запущенный PostgreSQL (проверено на версиях 16 и 18), Python 3.12, uv с поддержкой `--env-file`, Node.js 22 начиная с 22.22.2 и npm.

Под учётной записью администратора PostgreSQL создайте роль и пустую базу. Для роли задайте пароль по запросу `createuser`.

```sh
createuser -P keitaro
createdb -O keitaro keitaro
```

В корневом `.env` укажите в `DATABASE_URL` адрес `127.0.0.1`, порт PostgreSQL и пароль созданной роли. Переменные `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` нужны только для Compose. Выполните из корня репозитория.

```sh
cd frontend
npm ci
npm run build
cd ../backend
uv sync --locked
uv run --locked --env-file ../.env alembic upgrade head
uv run --locked --env-file ../.env python -m app.manage create-user operator
uv run --locked --env-file ../.env uvicorn app.main:app
```

Откройте `http://localhost:8000/`. Документация API доступна по адресу `http://localhost:8000/docs`.

## Пример работы

1. Войдите под созданной учётной записью. Укажите название кампании, выберите Австралию (`AU`), группу кампаний и источник трафика. Найдите оффер по названию или ID и нажмите «Создать кампанию». Если в Keitaro добавили группу или изменили доступность источника, нажмите «Обновить справочники».
2. В редакторе выберите созданную кампанию и нажмите «Загрузить». Откройте поток «Остальные страны». Начальная доля единственного оффера — 100%.
3. Найдите другой оффер и нажмите «Добавить». Для двух офферов без закреплений предпросмотр покажет по 50%. Кнопка «Обновить список кампаний» сохраняет открытый поток и черновик. Нажмите «Опубликовать», затем повторно загрузите кампанию и проверьте доли.
4. Если известная привязка была удалена в Keitaro, повторная загрузка покажет строку «Удалён» с долей 0%. Нажмите «Восстановить» и опубликуйте новый состав.

Если приложение сообщает, что не удалось подтвердить запись, сначала сверьте состояние кампании или потока в Keitaro.

## Проверки

Серверные тесты используют отдельную временную базу PostgreSQL и применяют к ней миграции. Задайте `TEST_DATABASE_URL` с подключением к тестовому серверу PostgreSQL под ролью с правом `CREATEDB`. Команды выполняются из корня репозитория.

```sh
cd backend
uv sync --locked
uv run --locked ruff check
uv run --locked ruff format --check
uv run --locked mypy
uv run --locked pytest
cd ../frontend
npm ci
npm run typecheck
npm test
npm run build
```

Для повторения примера без внешнего трекера запустите локальный стенд из `backend/` в отдельном терминале.

```sh
uv run --locked uvicorn keitaro_http:app --app-dir tests --port 9001
```

Для запуска приложения без Docker укажите в `.env` `KEITARO_URL=http://127.0.0.1:9001` и `KEITARO_API_KEY=local-test-key`. В стенде есть группа «Поиск», источники «Поисковая реклама» и «Партнёрская сеть» и офферы `3717`, `3749`, `11112` и `12130`.

Чтобы проверить обновление справочников, откройте форму и выберите «Поисковая реклама». Добавьте группу и архивируйте выбранный источник в стенде.

```sh
curl --fail -X PUT -H 'Content-Type: application/json' -d '{"name":"Новая группа"}' \
  http://127.0.0.1:9001/verification/groups/182
curl --fail -X DELETE http://127.0.0.1:9001/verification/traffic-sources/207
```

Если отправить заполненную форму до обновления, стенд вернёт HTTP 406. После обновления появится «Новая группа», а выбор архивного источника сбросится. Выберите новую группу и «Партнёрскую сеть», затем создайте кампанию. Запрос `GET /verification/state` возвращает журнал записи `campaign_writes` с исходными телами запросов.

На чистом стенде поток с офферами первой кампании получит ID `89`. Для проверки редактора создайте кампанию с оффером `3717`, добавьте остальные и опубликуйте четыре доли по 25%. Следующие команды удаляют две привязки напрямую в стенде и показывают его состояние.

```sh
curl --fail -X DELETE http://127.0.0.1:9001/verification/streams/89/offers/3749
curl --fail -X DELETE http://127.0.0.1:9001/verification/streams/89/offers/12130
curl --fail http://127.0.0.1:9001/verification/state
```

Повторно загрузите кампанию, закрепите 25% у `3717` и восстановите `3749`. Предпросмотр и подтверждённая публикация покажут `3717` — 25%, `11112` — 37%, `3749` — 38%. Состояние стенда сбрасывается при его перезапуске.
